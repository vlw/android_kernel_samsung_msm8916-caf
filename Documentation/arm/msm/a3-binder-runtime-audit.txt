===================================

Running handset: SM-A300F, kernel 3.10.108-g78dc491dd5b5-dirty, boot ID
976cc169-6c9f-4108-b171-3d2e1ed54cba. The following device results were
measured BEFORE the Binder changes documented here; no further reboot or
kernel installation was performed during this check.

AOSP binderThroughputTest:

   average 0.0942175 ms, worst 6.5526 ms, no transaction failures.
 - 4 workers x 4000 synchronous calls, 4096-byte payload:
   average 0.266011 ms, worst 8.39099 ms, no transaction failures.

The initial failed_transaction_log was empty. system_server, com.android.phone
and com.android.dialer each had zero pending transactions, available pool
threads and full free async space in the sampled state. These observations
exclude neither intermittent congestion nor an application-specific deadlock.

Targeted unmodified AOSP binderLibTest results:
 - NopTransaction and NopTransactionOneway passed 10 repetitions each.
 - OnewayQueueing failed 10/10 repetitions: callback 2 returned UNKNOWN_ERROR,
   exposing unexpected reentrant delivery of the pending oneway transaction.
 - DeathNotificationThread failed 2/2 repetitions, each taking about 5.1 s:
   callback wait timed out because the waiting thread's queue held its event.

Focused backports adapt these upstream Android fixes to our global-lock
3.10 driver rather than importing unrelated locking changes:

 - kernel/common 6f227409a179, "don't queue async transactions to thread":
   move the next queued async transaction to proc->todo and wake proc->wait.
 - kernel/common c825eca5ec45, "don't enqueue death notifications to thread
   todo": an already-dead reference's initial death notification belongs on
   proc->todo, so another available pool thread can deliver it.
 - kernel/common 4d666b500c2d, "call poll_wait() unconditionally": register
   the relevant waitqueue before reporting initial readiness. epoll may not
   provide another registration callback on later poll invocations.

Unsupported ioctl 0x40046210 is BINDER_ENABLE_ONEWAY_SPAM_DETECTION. Android
attempts this optional feature at process startup and tolerates its absence.
Its -EINVAL log is not a failed BC_TRANSACTION and is not silently implemented
as a successful no-op by these changes. binderfs is likewise absent; existing
/dev/binder, /dev/hwbinder and /dev/vndbinder devices are being used.


RT scheduling follow-up (2026-10-22)
----------------------------------
The complete 44-case AOSP suite on the previously installed kernel produced
39 passes, 3 harness skips and 2 failures: SchedPolicySet and InheritRt.
Both failures returned SCHED_NORMAL/0 instead of SCHED_RR/7 or SCHED_RR/8.
The old driver implemented nice-only inheritance and ignored the newer
flat_binder_object scheduling policy and inherit-RT bits.

Ported Android common e00eb41c0c7bea879d93e878748408e73357b384 (Martijn Coenen),
including its folded node-policy, opt-in RT, permission/restore and tracing
changes, to the globally locked staging driver. Both kernel UAPI copies must
advertise the same bits. Node priority is initialized in binder_new_node,
including legacy context-manager creation with fp == NULL. The receiver's
CAP_SYS_NICE/RLIMIT_RTPRIO/RLIMIT_NICE bound increases; restoring a saved
priority does not re-apply those limits. Async requests use the destination's
default policy rather than inheriting the caller. Task references cover early
priority setting of explicitly targeted nested-call threads.

3.10 adaptation: use sched/rt.h constants for priority conversion, retain the
global mutex instead of upstream fine-grained locks, restore before freeing
successful replies and on failed replies, and initialize trace arguments in
old/new/desired order. When RT inheritance is disabled, compare the node's
minimum against the effective fallback priority; this retains an explicit
fair node floor for RT callers too.

Host validation: tools/testing/selftests/binder/priority_test.py extracts
production helper bodies and the production transaction priority capture
block. ASan/UBSan tests cover conversion ranges, node RT policy, opt-in RT,
FIFO tie, receiver limits, nested restoration, repeated priority application,
unsupported caller policy and one-way fallback. The kernel/boot image builds.
These are scheduler-shim checks, not on-device acceptance of the new driver.
The phone still runs the previous kernel; the two AOSP RT tests and the full
suite must be rerun after a separately authorized installation/reboot.
